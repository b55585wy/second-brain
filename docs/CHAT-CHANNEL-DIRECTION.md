# 飞书与学习聊天的长期方向

2026-10-29 通道方向记录。产品总优先级以 [产品路线图](ROADMAP.md) 为准，近期交付以 [迭代计划](NEXT-ITERATION.md) 为准；本文保留飞书通道的选型与设计依据，不单独维护总排期。

私聊绑定、当前练习投递与回答保存已有本机验收，见 [飞书接入说明](FEISHU-CHAT.md)、[飞书验收](FEISHU-VERIFICATION-20261029.md) 和 [最新提炼及投递验收](MODEL-DIGEST-VERIFICATION-20261029.md)。当前“开始复习”命令投递今日练习，飞书内完整的思源到期卡片复习仍属计划。用户所说的 chatbox 指知行里的普通聊天框。飞书是可选交互通道；原简化版范围见 [简化目标](SIMPLICITY.md)。

## 已确认的长期目标

| 能力 | 用户体验 | 记录依据 |
| --- | --- | --- |
| 被动接收推送 | 在选择的时段收到一条值得处理的学习提醒，可稍后或暂停 | 提醒投递、延后和关闭状态 |
| 主动复习 | 在飞书或知行说“开始复习”，直接进入到期内容或一项练习 | 复习会话、用户回答、评分来源及帮助程度 |
| 学习进度 | 两个入口查看同一份目标、练习和复习历史 | 已完成输出、延迟回忆、不同任务中的应用证据 |
| 进度 AI 交互 | 询问“最近哪里有进步”“哪里还需要练”，回答关联具体记录 | 有时间与来源的表现摘要，未知项保留未知 |
| 成长式学习 | 依据表现和用户反馈调整难度、提示量与复习安排 | 相近条件下的多次表现及新情境任务结果 |

推送过、看过、答过、无提示回忆和在新情境中应用是不同事实。消息数、连续签到和模型赞扬不能直接证明能力增长。成长式学习的有效性仍需验证，参见 [研究草案](CHI-RESEARCH-PLAN.md)。

## 决策依据

聊天窗口能降低操作负担是待验证假设。长期需求需要可靠收发消息，也需要持续保存学习表现；仅转发消息无法提供后者。用户的注意力、每日学习时间和模型预算有限，新增入口不应要求重复维护目标、题目、进度或费用。

因此复用现有 Node/SQLite 学习核心，飞书和知行聊天框读取同一题目、写入同一练习记录。提醒发送已有题目，不调用模型；明确操作如开始复习、稍后、看进度优先用规则与本地查询处理，开放式解释和进度讨论再调用模型。

| 路线 | 已核实能力 | 对知行的判断 |
| --- | --- | --- |
| [飞书官方 Node SDK](https://github.com/larksuite/node-sdk) 的 [Channel](https://github.com/larksuite/node-sdk/blob/main/docs/channel.md) | 自定义消息处理、长连接、消息与卡片收发、自动重连、策略和去重缓存；[MIT 许可](https://github.com/larksuite/node-sdk/blob/main/LICENSE) | 首选验证：与当前 Node 后端直接衔接，无需启动编码代理 |
| 官方独立 [Channel SDK](https://github.com/larksuite/channel-sdk-node)（`@larksuite/channel`） | 面向代理与外部服务，基于上述 Node SDK；[MIT 许可](https://github.com/larksuite/channel-sdk-node/blob/main/LICENSE) | 同一技术路线的备选封装，实际集成选择一套公开接口，不重复接两套 |
| [cc-connect](https://github.com/chenhg5/cc-connect) | 多消息平台连接现成代理，具有会话、定时任务和外部平台 Bridge | 将来需要飞书远程操作 Codex 时评估。其 [Bridge](https://github.com/chenhg5/cc-connect/blob/main/docs/bridge-protocol.md) 是外部平台接代理引擎，不代表现成支持知行作为自定义业务后端 |
| [Feishu Codex Bridge，lengjingxu 版本](https://github.com/lengjingxu/feishu-codex-bridge) | 飞书项目群/话题映射本机 Codex 会话、进度和审批；[MIT 许可](https://github.com/lengjingxu/feishu-codex-bridge/blob/main/LICENSE) | 参考会话路由和重启恢复；学习收发优先调用知行自身能力。其他同名仓库需单独评估 |

截至此次核对，cc-connect 的 README 声明 MIT，但根目录未找到 LICENSE 文件，GitHub 许可字段为空；采纳其代码作商业分发前需核实完整授权文本。官方 SDK 的 MIT 文本允许商业使用并要求保留版权及许可声明；具体产品仍需核对选定版本及其依赖，不能把 SDK 许可等同于全部产品的许可。

现有思源连接继续提供笔记和原生复习能力。学习进度由知行保留练习与输出证据，复习调度按所接原生卡片状态执行；不同时引入第二套调度算法来改写同一卡片，也不把记忆调度预测当作职业技能掌握度。

## 分阶段交付

1. **飞书与网页打通。** 绑定一个允许用户，先支持私聊文本：发送今日练习、回答、开始复习、稍后和暂停。网页能看到飞书提交，两个入口不会重复提交同一操作。
2. **可追溯的进度。** 按目标聚合学习记录，区分活动完成与表现证据；可查看日期、题目、帮助程度、自评或反馈来源。原始输出保留，档案变化不覆盖历史记录。
3. **基于进度的 AI 对话。** 使用相关练习片段和本地统计回答问题，给出引用与下一项可做的练习。不反复加载全部 Codex 历史，不凭空生成掌握率。
4. **适应表现的安排。** 根据延迟回忆、应用任务和用户反馈调整题目难度、提示和间隔；逐步从解释到应用，再到新情境检查。时间预算和暂停设置优先于追加任务。

第一阶段的完成条件是双入口记录一致、重复消息不重复写入、暂停后不发送新提醒、断线重启可恢复、不影响已有复习与输出。卡片按钮需在飞书实际配置中单独验证后再加入，文本收发先形成可用闭环。

## 可靠性与费用约束

SDK 内置去重缓存不能替代业务持久幂等。入站事件先持久化并用事件或消息标识去重，再执行答案写入或模型调用；提醒按用户、练习和通道设置稳定投递键，发送失败不重新选题或评分。具体订阅与回调规则按 [飞书事件文档](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/event-subscription-guide/event-subscriptions)验证。

默认推送可控制在每天一次摘要或练习提醒，并支持安静时段、延后和暂停；这是待验证的产品默认值。提炼频率、推送频率和用户主动复习分别调度。预生成题目的再次投递与本地查询不增加模型调用；后续 AI 进度讨论须有单独可见的调用预算，不能误称由当前自动整理每日三次上限覆盖。

本地长连接要求电脑、网络和进程持续在线。若要电脑关机后仍可在手机学习，需另行部署常在线服务，或云端缓存已生成题目并与本地采集器同步；账号绑定、权限、同步与部署需另作交付。
