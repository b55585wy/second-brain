# 飞书学习入口

0.3.0–0.3.3 的已验收基线使用飞书官方 Node SDK 1.76.0 的 Channel 接收私聊，以原生消息 API 的稳定 UUID 发送文本；二维码由 qrcode 1.5.4 在本机生成，已打通今日练习与回答。

本机已部署 **0.6.1**。发送“菜单”打开四入口卡片；真实“今日练习”点击、同一消息上的题目更新和确认后的作答关联已验证，见 [题目修复验收](FEISHU-PRACTICE-CARD-VERIFICATION-20261031.md)及[原菜单验收](FEISHU-MENU-VERIFICATION-20261031.md)。原有机器人、绑定、回答和讨论继续保留；0.5已有一轮真实讨论，教学调整与明确保存的边界见 [讨论验收](ADVICE-DISCUSSION-VERIFICATION-20261031.md)。云端发布以 GitHub Release 为准；进度教练、自适应安排及自由聊天继续按 [长期方向](CHAT-CHANNEL-DIRECTION.md)迭代。

## 第一次接入

1. 打开知行的 **偏好设置 → 飞书学习**，点击 **扫码连接飞书**。用飞书扫描页面二维码，按官方页面创建应用并确认权限。凭据由程序保存到本机，不粘贴到聊天中。
2. 等待页面显示连接状态。扫码完成只说明应用凭据已保存；如飞书要求发布应用或管理员审核，先完成相应步骤。
3. 在网页点击 **打开飞书私聊**；也可展开 **手机扫码打开**，用手机进入同一个机器人。点击获取绑定码，在私聊中发送页面给出的 **绑定 XXXX-XXXX-XXXX**。验证码十分钟有效，一次使用；不需要创建群聊、查询用户 ID 或会话 ID。已绑定时直接使用会话入口，不必重新获取绑定码。
4. 有有效的今日练习时，绑定后自动投递。直接回答，或用 **独立：**、**提示：**、**部分代写：**、**AI代写：** 如实注明帮助程度。未注明时记为未知。打开网页「今天」可见同一条输出和本地自查提示。

当前没有有效题目时不会临时增加模型调用。原有自动整理按自身预算运行，准备好后按提醒设置投递。

## 0.4 可选学习卡片

已有机器人与私聊绑定后，在 **偏好设置 → 飞书学习 → 学习卡片** 点击 **扫码启用学习卡片**，为当前应用补充 `card.action.trigger` 回调。保留现有绑定；授权完成后还需实际点击一次按钮，确认回调连通。租户要求发布或管理员审核时，按飞书页面完成。

卡片支持回答、查看建议、保存建议、暂不采纳和记忆闪卡。**保存建议**进入网页已有的“成果”，默认先收藏，不自动把全部建议同步到思源；**暂不采纳**只记录选择，保留原回答、建议及已保存成果。表单回答限 1000 字，长回答可直接发私聊文字。

记忆闪卡沿用思源原生到期复习，先回忆、翻面，再选择忘记／困难／记得／轻松；没有到期卡时可明确选择用本次学习重点制作一张，内容仍标为未核验。精确兼容版本为思源 **3.8.8、3.8.9**，3.8.9 已有[独立真实 HTTP 验收](SIYUAN-389-VERIFICATION-20261030.md)。按钮含义、次数和故障恢复见 [学习卡片](FEISHU-LEARNING-CARDS.md)。

## 0.5：先讨论，再保存

在建议卡片 **继续讨论** 中输入问题并点 **发送补充**，也可引用那条建议消息回复。回复围绕原题、原回答及原建议准备修订草稿，不重交或改写原回答。**原建议**与**第 N 次修改**保留版本，满意后点击 **保存建议**才将当前版本收进现有成果；后续讨论不会覆盖已保存的旧版。

“OK”“好的”“谢谢”仅确认收到，不调用模型、不创建成果。生成中不可保存，旧按钮不能采纳未看过的新版本。历史建议可在当前授权和绑定有效时引用讨论，遇到新练习时不会把不明引用猜成作答。每轮新 AI 讨论与点评共用日额度，失败和结果不明不自动重发。本轮主要使用飞书入口，不新建通用聊天应用或网页聊天面板。详见 [讨论契约](ADVICE-DISCUSSION-API.md)和[验收进度](ADVICE-DISCUSSION-VERIFICATION-20261031.md)。

## 飞书要求补充配置时

在 [飞书开发者后台](https://open.feishu.cn/app)找到刚创建的应用：启用机器人；授予应用身份的 `im:message.p2p_msg:readonly` 和 `im:message:send_as_bot`；事件订阅增加 `im.message.receive_v1`，选择长连接接收；按租户要求创建版本并发布，可用范围包含本人。

官方扫码接口的权限预填受平台支持情况影响，不能保证每个租户扫码后自动完成全部步骤。依据：[官方注册接口](https://github.com/larksuite/node-sdk#app-registration)、[事件接入](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/event-subscription-guide/event-subscriptions)、[机器人发布](https://open.feishu.cn/document/client-docs/bot-v3/bot-overview)。

扫码不可用时，原有高级设置仍支持填写自己应用的 App ID / App Secret；模型、调度及已有资料保持独立。二维码过期或准备超过三十秒可重新开始。取消、过期或本地飞书配置已变化时，迟到的旧授权回执不写入配置。

## 日常操作

发送 **菜单** 可以打开卡片入口：**今日练习、记忆闪卡、查看已有建议、当前状态**。也可发送“帮助”打开同一入口。没有今日练习也能查看菜单；未开启卡片时返回文字说明。

“今日练习”在当前菜单消息里展示题目；题目确认显示后才接受回答。“查看已有建议”只读取已有内容，不主动生成新点评。打开菜单和查看状态不调用模型，发送“点评”仍沿用原有开关与额度。

| 私聊内容 | 行为 |
| --- | --- |
| 菜单、menu、帮助、help | 打开四入口菜单；卡片关闭时返回文字操作说明 |
| 今日练习、开始学习 | 获取当前有效题目，已发送或已完成时给出实际状态 |
| 直接回答或回复题目 | 保存一次输出，并生成本地自查提示 |
| 点评、回答建议 | 0.4 查看本次回答的 AI 建议；已有结果直接复用，未准备时受开关与额度约束 |
| 重新点评、重试点评 | 0.4 明确请求一次失败重试，继续计入独立点评额度 |
| 暂停、暂停提醒 | 暂停主动提醒，保留已有回答 |
| 继续、恢复提醒 | 恢复提醒 |
| 稍后、稍后30分钟 | 延后约三十分钟 |

默认按学习档案时区每日 09:00 提醒，可在页面改时间或关闭。发送已有题目、保存回答与本地自查不调用付费模型。0.4 自动点评默认关闭，开启后由新回答触发，初始上限 3 次/天，可设 0–20 次，与自动提炼额度分开；失败和结果不明均计入，不隐式修复重发。查看已有建议、保存或暂不采纳、已有闪卡复习不额外调用模型。AI 建议和记忆自评不代表事实核验或能力掌握。程序或电脑关闭期间不会实时收发，桌面入口继续负责启动服务。

0.5 的一次新讨论同样占用上述点评额度；重复消息复用原任务，查看已有解释、发送简短确认和明确保存均不额外请求模型。网络使用可选的本机受限代理配置时，也不会新增自动重试或改变模型费用规则，日常用户无需反复配置网络。

## 接口与持久状态

所有接口沿用 `/api/v1` 信封、回环访问、写入客户端标记和 operationId。GET 不创建应用、发送消息或执行采集。

| 接口 | 作用 |
| --- | --- |
| GET /feishu-chat | 返回配置、绑定布尔值、连接状态、时间与错误摘要，不返回接收人标识或密钥 |
| GET /feishu-chat/entry | 返回当前已配置应用的官方私聊 AppLink 和本地二维码；未配置或未验证区域返回两个 null，不发送消息 |
| PUT /feishu-chat | 配置 enabled、remindersEnabled、reminderLocalTime、cardsEnabled，要求 expectedRevision |
| POST /feishu-chat/pair | 显式生成一次性验证码，重新配对会撤销旧绑定 |
| POST /feishu-chat/send-today | 仅向已绑定自己投递当前题目，区分 queued、alreadySent、completed、deliveryState |
| POST /feishu-chat/open-menu | 使用operationId明确向已绑定自己打开菜单，不创建个人收件或作答 |
| GET /feishu-chat/registration | 读取扫码会话；waiting 含官方原始 URL、本地二维码 data URL 和到期时间 |
| POST /feishu-chat/registration | 显式启动一项扫码流程，进行中请求合并；完成后单独检查连接就绪 |
| POST /feishu-chat/registration/cancel | 中止当前扫码并拒绝其迟到结果 |
| GET /feishu-chat/cards/registration | 读取当前应用的学习卡片扫码会话 |
| POST /feishu-chat/cards/registration | 为当前机器人显式开始卡片回调授权，保留原凭据和绑定 |
| POST /feishu-chat/cards/registration/cancel | 中止卡片扫码，拒绝迟到回执 |
| GET /advice-settings；PUT /advice-settings | 读取或更新自动点评开关和独立日额度；写入要求 expectedRevision |
| GET /attempts/:id/advice；POST /attempts/:id/advice | 读取同一点评或显式安排点评／重试；读取不发起模型请求 |

0.5 的讨论读取、提交、重试与按版本保存接口见 [完整讨论API](ADVICE-DISCUSSION-API.md)；GET 不创建讨论记录或发起模型调用。

绑定限定应用身份、用户和私聊。更换凭据、重新绑定或关闭后，旧客户端事件及待发消息不会进入新接收人。发送中仅调整提醒时间不丢失已经送达题目的回答关联；题目、来源或目标失效则拒绝旧题作答。

“扫码连接飞书”用于初次创建和授权应用；“手机扫码打开”用于进入已配置的机器人。私聊入口采用飞书官方 [AppLink 打开机器人会话](https://open.larkoffice.com/document/develop-an-echo-bot/introduction)，当前验收区域为中国飞书。创建或选择群聊需要另外的群权限、目的地绑定和成员消息隔离，本阶段保留私聊。

入站去重、答案与 outbox 持久保存；答案和消息身份在同一 SQLite 事务提交。确认收到远端 message_id 才建立题目关联。发送结果不明记为 uncertain，不自动盲目重发；明确未提交的可重试错误最多三次，间隔一分钟。服务端 UUID 不被当作无限期去重保证。

回答、反馈、保存的成果、建议选择及0.5讨论历史／候选版本沿现有备份导出，包含 unknown 帮助程度；应用密钥、绑定、二维码、验证码、卡片回调令牌、模型调用账本及待执行任务不作为可恢复权限导出。导入不会给新机器自动开启飞书或模型，也不会恢复接收人；未完成讨论恢复为不可自动执行的历史。默认省略来源正文的备份不会把缺失正文当作已读取依据。
