# 飞书学习入口：第一步

0.3.0 使用飞书官方 Node SDK 1.76.0 的 Channel 接收私聊，以原生消息 API 的稳定 UUID 发送文本；二维码由 qrcode 1.5.4 在本机生成。本阶段打通今日练习与回答，网页自由聊天、原生卡片复习和进度 AI 教练继续按 [长期方向](CHAT-CHANNEL-DIRECTION.md)迭代。

## 第一次接入

1. 打开知行的 **偏好设置 → 飞书学习**，点击 **扫码连接飞书**。用飞书扫描页面二维码，按官方页面创建应用并确认权限。凭据由程序保存到本机，不粘贴到聊天中。
2. 等待页面显示连接状态。扫码完成只说明应用凭据已保存；如飞书要求发布应用或管理员审核，先完成相应步骤。
3. 在网页点击 **打开飞书私聊**；也可展开 **手机扫码打开**，用手机进入同一个机器人。点击获取绑定码，在私聊中发送页面给出的 **绑定 XXXX-XXXX-XXXX**。验证码十分钟有效，一次使用；不需要创建群聊、查询用户 ID 或会话 ID。已绑定时直接使用会话入口，不必重新获取绑定码。
4. 有有效的今日练习时，绑定后自动投递。直接回答，或用 **独立：**、**提示：**、**部分代写：**、**AI代写：** 如实注明帮助程度。未注明时记为未知。打开网页「今天」可见同一条输出和本地自查提示。

当前没有有效题目时不会临时增加模型调用。原有自动整理按自身预算运行，准备好后按提醒设置投递。

## 飞书要求补充配置时

在 [飞书开发者后台](https://open.feishu.cn/app)找到刚创建的应用：启用机器人；授予应用身份的 `im:message.p2p_msg:readonly` 和 `im:message:send_as_bot`；事件订阅增加 `im.message.receive_v1`，选择长连接接收；按租户要求创建版本并发布，可用范围包含本人。

官方扫码接口的权限预填受平台支持情况影响，不能保证每个租户扫码后自动完成全部步骤。依据：[官方注册接口](https://github.com/larksuite/node-sdk#app-registration)、[事件接入](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/event-subscription-guide/event-subscriptions)、[机器人发布](https://open.feishu.cn/document/client-docs/bot-v3/bot-overview)。

扫码不可用时，原有高级设置仍支持填写自己应用的 App ID / App Secret；模型、调度及已有资料保持独立。二维码过期或准备超过三十秒可重新开始。取消、过期或本地飞书配置已变化时，迟到的旧授权回执不写入配置。

## 日常操作

| 私聊内容 | 行为 |
| --- | --- |
| 今日练习、开始学习 | 获取当前有效题目，已发送或已完成时给出实际状态 |
| 直接回答或回复题目 | 保存一次输出，并生成本地自查提示 |
| 暂停、暂停提醒 | 暂停主动提醒，保留已有回答 |
| 继续、恢复提醒 | 恢复提醒 |
| 稍后、稍后30分钟 | 延后约三十分钟 |
| 帮助 | 查看支持的操作 |

默认按学习档案时区每日 09:00 提醒，可在页面改时间或关闭。发送已有题目、保存回答与本地反馈不调用付费模型，不代表自动评估了答案正确性或技能掌握。程序或电脑关闭期间不会实时收发，桌面入口继续负责启动服务。

## 接口与持久状态

所有接口沿用 `/api/v1` 信封、回环访问、写入客户端标记和 operationId。GET 不创建应用、发送消息或执行采集。

| 接口 | 作用 |
| --- | --- |
| GET /feishu-chat | 返回配置、绑定布尔值、连接状态、时间与错误摘要，不返回接收人标识或密钥 |
| GET /feishu-chat/entry | 返回当前已配置应用的官方私聊 AppLink 和本地二维码；未配置或未验证区域返回两个 null，不发送消息 |
| PUT /feishu-chat | 配置 enabled、remindersEnabled、reminderLocalTime，要求 expectedRevision |
| POST /feishu-chat/pair | 显式生成一次性验证码，重新配对会撤销旧绑定 |
| POST /feishu-chat/send-today | 仅向已绑定自己投递当前题目，区分 queued、alreadySent、completed、deliveryState |
| GET /feishu-chat/registration | 读取扫码会话；waiting 含官方原始 URL、本地二维码 data URL 和到期时间 |
| POST /feishu-chat/registration | 显式启动一项扫码流程，进行中请求合并；完成后单独检查连接就绪 |
| POST /feishu-chat/registration/cancel | 中止当前扫码并拒绝其迟到结果 |

绑定限定应用身份、用户和私聊。更换凭据、重新绑定或关闭后，旧客户端事件及待发消息不会进入新接收人。发送中仅调整提醒时间不丢失已经送达题目的回答关联；题目、来源或目标失效则拒绝旧题作答。

“扫码连接飞书”用于初次创建和授权应用；“手机扫码打开”用于进入已配置的机器人。私聊入口采用飞书官方 [AppLink 打开机器人会话](https://open.larkoffice.com/document/develop-an-echo-bot/introduction)，当前验收区域为中国飞书。创建或选择群聊需要另外的群权限、目的地绑定和成员消息隔离，本阶段保留私聊。

入站去重、答案与 outbox 持久保存；答案和消息身份在同一 SQLite 事务提交。确认收到远端 message_id 才建立题目关联。发送结果不明记为 uncertain，不自动盲目重发；明确未提交的可重试错误最多三次，间隔一分钟。服务端 UUID 不被当作无限期去重保证。

回答和反馈沿现有备份导出，包含 unknown 帮助程度；应用密钥、绑定、二维码、验证码及收发队列不作为可恢复权限导出。导入不会给新机器自动开启飞书或恢复接收人。
