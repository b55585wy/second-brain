# 飞书学习卡片

卡片把学习动作放在原消息中：**回答 → 看建议 → 继续讨论 → 满意后保存当前建议 → 记忆闪卡**。卡片界面由 Kimi CLI 实现，业务、存储和评分由 Codex 接入。

本机已部署0.6.0，新增四入口菜单，真实菜单投递一次获平台接受，新菜单按钮仍待实际点击验证，见 [菜单验收](FEISHU-MENU-VERIFICATION-20261031.md)。0.4原卡片的投递与按钮回调已确认，0.5已有一轮真实讨论；0.5.1允许先讲解及完整参考示例，保存时带上讲解，新教学表现和明确采纳仍待用户使用验证，见 [讨论验收](ADVICE-DISCUSSION-VERIFICATION-20261031.md)。

## 启用一次

在知行的 **偏好设置 → 飞书学习 → 学习卡片** 点击 **扫码启用学习卡片**，用飞书为已经连接的机器人补充卡片回调授权。沿用当前机器人与私聊绑定，不必建立群聊、查询 ID 或重新填写密钥。

扫码完成说明授权流程结束。页面还会显示是否收到过当前绑定下的有效按钮操作；需要在飞书点一次卡片按钮，才能确认回调实际连通。如果租户要求发布应用或管理员审核，先完成飞书官方页面上的步骤。

知行后台需要运行。关闭网页不影响后台，关闭后台或电脑则无法即时收发。

## 每个按钮做什么

在知行学习机器人私聊发送 **菜单**，可以直接点 **今日练习、记忆闪卡、查看已有建议、当前状态**。无需记住所有指令；发送“菜单”可重新回到入口。打开菜单、查看已有建议和查看状态不生成新的AI内容。

| 操作 | 结果 |
| --- | --- |
| 提交回答 | 保存本次回答；可注明独立完成或借助程度。卡片表单限 1000 字，长回答可直接发私聊文本。 |
| 查看建议 | 查看这次回答的“已做到、待改进、下一步”。已完成的建议直接复用；准备中显示状态。 |
| 继续讨论／发送补充（0.5） | 提问、补充情境或要求解释，生成修订草稿；也可引用该条建议消息回复，不重交原练习。 |
| 保存建议 | 明确采纳当前看到的可用版本，收藏到知行已有成果，带上原练习目标和来源；有讨论回复时，一并保留“本轮讲解（AI参考）”。同版本重复保存不重复创建成果；后续修改稿不会覆盖已收藏的旧版。 |
| 暂不采纳 | 记录当前选择，保留回答、建议及已经收藏的成果；不会删除历史。之后仍可重新保存。 |
| 记忆闪卡 | 进入思源原生到期复习；没有到期卡时，可以明确选择用本次学习重点制作一张。 |
| 翻面 | 先自己回忆，再显示答案。翻面前不能评分。 |
| 忘记／困难／记得／轻松 | 记录本次记忆自评，交给思源原生调度；评分确认前不继续重复发送。 |

用学习重点制作闪卡，需要兼容的思源连接。点击制作表示你选择保留这条知识，内容仍标为未核验。新卡沿用已有同步与复习机制，不额外调用模型。

保存的建议可在网页 **高级工具 → 练习与输出 → 成果** 中查看。默认先收进知行；本轮没有把所有建议自动同步到思源。

0.5 将版本显示为 **原建议**或**第 N 次修改**。讨论回复和候选修改都先保留为草稿，只有点击“保存建议”才收藏；“OK”“好的”“谢谢”是本地确认收到，不请求 AI，也不代表采纳。生成中或旧卡片的按钮不能替你采纳尚未看到的新版本。网页保留原点评与已有成果，本轮不增加独立聊天页面。

## 次数与失败

新回答的自动点评由 **偏好设置 → 自动点评** 控制，默认关闭，开启后的初始上限为 3 次/天，可设置为 0–20 次。它与自动整理对话的每日额度分开。调用失败或结果不明也计入次数；不会悄悄再次付费请求。旧回答只有明确请求时才补点评。

0.5 的每轮新 AI 讨论与上述点评共用同一额度，每个请求最多一次模型调用，不另建隐藏额度。每条补充最多1000字，只带有界的原题、原回答、原建议及最近讨论；完整本机历史保留。超时、格式错误或结果不明时不自动修复重发，明确重试才会占用一次新请求。

翻面、查看已完成建议、保存或暂不采纳、已有闪卡复习均不额外调用模型。模型不可用时仍保留回答与本地自查；本地自查不代表正确性评估。AI 建议和记忆自评也不能证明事实已经核实或长期能力已经掌握。

卡片失效、题目或来源变动时，先刷新状态或发送“今日练习”。结果不明的保存、发送和评分不盲目重做。已保存的原始回答保留。

明确请求的卡片如果被平台拒绝或投递结果未确认，会补一条简短文字提示；这条提示本身不会继续生成提示。未确认的原卡片保持原状，不自动重复投递。可以发送“菜单”，从新菜单查看当前题目。

“稍后”表示把提醒延后约 30 分钟；“暂停”表示停止主动提醒，已有回答继续保留。这两项属于提醒控制，不占学习卡片的主要按钮。

## 技术边界

使用飞书 Card 2.0 与当前应用的 `card.action.trigger` 回调。按钮绑定应用身份、私聊用户、已确认消息和该条原题／回答；回调先入队，模型与思源操作在后台处理。引用历史建议仍须通过当前材料授权与绑定检查，授权或来源变化会阻止外发与发布。授权成功本身不能代替真实按钮连通验收。

原回答、反馈、收藏成果、当前建议选择及0.5讨论历史／候选版本进入正常备份；应用密钥、私聊绑定、卡片回调令牌及待执行任务不会作为可恢复权限导出。导入备份不会自动开启飞书或模型调用。没有随备份保存的来源正文按缺失处理，不伪造来源来补齐上下文。
