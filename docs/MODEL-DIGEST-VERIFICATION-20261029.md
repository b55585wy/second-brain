# 提炼格式校验修复 · 0.3.2

## 问题与已知范围

真实请求曾返回可解析的 JSON，但结构校验失败。旧版本只保留统一错误，没有保存失败字段或原始响应，因此不能反推旧请求的确切失败条件。

已确认旧提示遗漏了校验器执行的多项硬限制，包括证据条数、评分项条数及部分文本长度。JSON Output 只保证合法 JSON，应用仍需声明并校验自己的字段契约；[DeepSeek 官方说明](https://api-docs.deepseek.com/guides/json_mode/)同时要求提供格式示例。

## 修复

- `server/model-digest.mjs` 共用字段上限构造提示与校验器，提供合法 JSON 示例，并明确示例来源不属于实际证据。
- 所有引用仍须匹配输入来源及连续原文，索引与预算保持严格整数校验；不会截断结果、补造字段或改写引用来通过校验。
- 错误只包含固定字段路径与固定原因；调用记录中的 `validationIssue` 不包含模型原文、未知字段名或值。
- 每个自动提炼尝试仍只有一次模型调用；格式错误不触发快速修复重发，失败记录与待处理收据保留。

## 隔离验证

源代码副本后端 **508/508**、打包 **35/35** 全部通过，无跳过。覆盖所有文本 Unicode 边界、数组数量、整数索引、精确引用、恶意额外字段、零重点、零预算，以及失败后恢复。前端没有修改。
