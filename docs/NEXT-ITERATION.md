# 知行短期迭代计划

更新：2026-10-30。本机已部署本地单用户 Beta **0.4.0**，完整回归及一次既有回答的真实 DeepSeek 点评通过；学习卡片仍待用户扫码和真实按钮闭环验收。本文中的勾选表示实现进度，不替代未完成的交付门槛；云端发布以 GitHub Release 为准。长期目标与取舍见 [产品路线图](ROADMAP.md)，实际完成情况以 [实施状态](IMPLEMENTATION-STATUS.md) 和验收记录为准。

## 目标与依据

下一步先让用户完成“收到练习 → 独立回答 → 获得具体点评 → 知道下一步”的闭环。日常继续使用一个保存动作，网页与飞书共用记录。

已确认的约束是用户时间有限、模型请求有成本、一次提交只能证明发生了这次输出。待验证的假设是：简短且有依据的点评能减少用户自行判断下一步的负担。交付优先级按这个可观察结果排列，功能数量和生成条数不作为学习效果证据。

## I1：回答后的自动 AI 点评——已部署，飞书卡片闭环待验收

以下实现项已接入并通过最终隔离回归，本机已部署且完成一次原有回答的真实模型点评，没有重新交卷。飞书扫码、真实按钮操作及新交卷后的网页／飞书卡片一致性仍是完成门槛；不将实现或单次验收等同于已验证学习成效。

### 用户体验与范围

- [x] 使用现有 DeepSeek 配置，在偏好设置中一次性选择自动点评；新回答保存后自动准备点评，每次作答不再增加确认步骤。
- [x] 点评默认呈现“已做到、待改进、下一步”，已做到与待改进各最多两条，只建议一个下一步动作；依据和详情按需展开。
- [x] 网页与飞书复用同一份点评记录；先确认回答保存，再显示点评准备中、完成或失败，点评失败不要求重新交卷。
- [x] 未开启、额度不足或模型失败时，继续提供明确标注的本地自查；文案说明实际状态，不把模板说成 AI 批改，也不把未安排的任务说成正在评估。
- [x] 旧回答可显式补一次点评；升级或开启功能不自动批改全部历史。

### 点评依据与边界

- [x] 输入包含原题、原评分要点、用户回答和预算内的授权依据，说明实际检查范围。不能只看回答字数就给出正确或掌握结论。
- [x] 评价逐项关联回答原文片段；缺证据或无法判断时保留“未评估”。来源摘录存在不等于已验证其中的事实。
- [x] 对无法核实的领域事实保留未知，提供补充检查方向；本迭代不增加全网自动检索，也不承诺完整事实核验。
- [x] 长回答保留全文，点评输入与输出有明确上限；只覆盖部分内容时标明范围，不声称审阅了全文。
- [x] 当前题目、回答、来源及点评身份绑定；授权撤销或外部模型处理关闭后不继续外发。历史结果保留原目标，不因档案更新而重写原答案。

### 次数、可靠性与数据

- [x] 点评预算与自动提炼每天三次的预算分开。自动点评默认关闭，开启后的初始上限为 **3 次/天**，设置中可见并可调整为 **0–20 次**。
- [x] 调用前预留次数，失败与结果不明均计入；若供应商返回 token 用量则记录，未返回记为未知，不记作零消耗。
- [x] 同一回答的同一次点评请求使用持久身份；重复点击、重复飞书消息、轮询和重启不重复发起同一模型请求。
- [x] 格式错误和结果不明不进行隐式修复重发；已成功的结果直接复用，失败重试必须是明确的一次新操作，并继续受预算限制。
- [x] 原始回答、旧反馈和失败记录保留；在 A 的反馈返回时已切到 B，不覆盖 B 的草稿、反馈或题目。

### I1 完成门槛

| 场景 | 必须观察到的结果 |
| --- | --- |
| 网页、飞书正常交卷 | 原回答保存一次，产生一次点评，两处读取同一结果；无需用户再去高级工具找入口 |
| 空回答、无模型配置、开关关闭、零额度或已超限 | 按实际条件拦截或保存并提供本地自查；不发生未安排的模型调用 |
| 重复事件、重复操作、在途重启 | 不重复保存回答或发送相同点评请求；结果不明的调用不会盲目重发 |
| 超时、鉴权失败、无效 JSON、无效引用或评分字段 | 原回答仍在，失败有可理解的状态且计入次数，不伪造成功反馈 |
| 证据不足、长回答、预算边界 | 未知项保留未知，覆盖范围清楚，输入/输出与每日次数均有界 |
| 切题、档案更新、来源变化或权限撤销 | 旧反馈不污染新题；历史仍可查看，外发与结果提交遵守当前授权 |
| 原有流程回归 | 当日题目与草稿稳定，自动提炼次数规则不变，已有思源复习和导出继续可用 |
| 真实闭环 | 在明确额度内完成至少一次真实交卷、点评与飞书/网页一致性检查；标注模型建议及未验证项 |

后端测试只在源码隔离副本运行，使用合成数据与假上游；真实模型验收单独进行并记录次数。前端由 Kimi 实现，Codex 做集成验证。只改文档时不运行应用测试，也不改运行配置。

真实 DeepSeek 已完成一次既有回答点评，仅一次请求；验收时日额度 3、已用 1、剩余 2。当前卡片扫码等待用户，仍需实际点击按钮并核对新交卷后的两个入口结果。已有模型点评与思源 3.8.9 独立真实 HTTP 验收不能代替真实飞书卡片验收。完整证据见 [0.4 验收记录](ANSWER-ADVICE-VERIFICATION-20261030.md)。

## 范围与维护

本轮不迁移到 Notion、不扩展默认采集范围、不建立新聊天客户端，也不建设多租户或云端常在线服务。相关候选工作保留在 [长期路线](ROADMAP.md)。

每个迭代验收后：更新本文复选项、[实施状态](IMPLEMENTATION-STATUS.md) 和对应验收证据，再进入下一优先级。计划变更记录原因与对用户操作、时间预算和数据的影响；没有验收证据的条目继续标为未完成。
