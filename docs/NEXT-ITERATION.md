# 知行短期迭代计划

更新：2026-10-29。基线：本地单用户 Beta **0.3.2**。本文是待实施计划，未勾选事项均未交付；没有承诺发布日期。长期目标与取舍见 [产品路线图](ROADMAP.md)，实际完成情况以 [实施状态](IMPLEMENTATION-STATUS.md) 和验收记录为准。

## 目标与依据

下一步先让用户完成“收到练习 → 独立回答 → 获得具体点评 → 知道下一步”的闭环。日常继续使用一个保存动作，网页与飞书共用记录。

已确认的约束是用户时间有限、模型请求有成本、一次提交只能证明发生了这次输出。待验证的假设是：简短且有依据的点评能减少用户自行判断下一步的负担。交付优先级按这个可观察结果排列，功能数量和生成条数不作为学习效果证据。

## I1：回答后的自动 AI 点评——下一优先级

### 用户体验与范围

- [ ] 使用现有 DeepSeek 配置，在偏好设置中一次性选择自动点评；新回答保存后自动准备点评，每次作答不再增加确认步骤。
- [ ] 点评默认呈现“已做到、待改进、下一步”三块，每块最多两条，只建议一个下一步动作；依据和详情按需展开。
- [ ] 网页与飞书查看同一份点评；先确认回答保存，再显示点评准备中、完成或失败，点评失败不要求重新交卷。
- [ ] 未开启、额度不足或模型失败时，继续提供明确标注的本地自查；文案说明实际状态，不把模板说成 AI 批改，也不把未安排的任务说成正在评估。
- [ ] 旧回答可显式补一次点评；升级或开启功能不自动批改全部历史。

### 点评依据与边界

- [ ] 输入包含原题、原评分要点、用户回答和预算内的授权依据，说明实际检查范围。不能只看回答字数就给出正确或掌握结论。
- [ ] 评价逐项关联回答片段和可核对依据；缺证据或无法判断时保留“未评估”。引用存在不等于已验证其中的事实。
- [ ] 对无法核实的领域事实列出待核对项；本迭代不增加全网自动检索，也不承诺完整事实核验。
- [ ] 长回答保留全文，点评输入与输出有明确上限；只覆盖部分内容时标明范围，不声称审阅了全文。
- [ ] 当前题目、回答、来源及点评身份绑定；授权撤销或外部模型处理关闭后不继续外发。历史结果保留原目标，不因档案更新而重写原答案。

### 次数、可靠性与数据

- [ ] 点评预算与自动提炼每天三次的预算分开。拟定点评默认上限为 **3 次/天**，设置中可见、可调整；这是计划值，当前版本没有这个开关和额度。
- [ ] 调用前预留次数，失败与结果不明均计入；若供应商返回 token 用量则记录，未返回时显示未知，不记作零消耗。
- [ ] 同一回答的同一次点评请求使用持久身份；重复点击、重复飞书消息、轮询和重启不重复发起模型请求。
- [ ] 格式错误和结果不明不进行隐式修复重发；已成功的结果直接复用，失败重试必须是明确的一次新操作，并继续受预算限制。
- [ ] 原始回答、旧反馈和失败记录保留；在 A 的反馈返回时已切到 B，不覆盖 B 的草稿、反馈或题目。

### 实施分工与顺序

| 工作项 | 负责人 | 涉及位置与交付物 |
| --- | --- | --- |
| F1：确定输入依据、输出契约和独立预算 | Codex | [learning](../server/learning.mjs)、[model](../server/model.mjs)、[settings](../server/settings.mjs)；先写需求场景和接口约定 |
| F2：异步点评、持久调用身份、缓存与失败状态 | Codex | [jobs](../server/jobs.mjs)、[API](../server/app.mjs)；复用现有任务与反馈记录 |
| F3：飞书提交后触发点评并投递结果 | Codex | [feishu-chat](../server/feishu-chat.mjs)；复用既有收件、发件和绑定身份 |
| F4：首页、练习页和设置的简洁交互 | Kimi，通过 Kimi CLI | [TodayPage](../frontend/src/pages/TodayPage.tsx)、[PracticePage](../frontend/src/pages/PracticePage.tsx)、[SettingsPage](../frontend/src/pages/SettingsPage.tsx)；按 Codex 接口约定实现 |
| F5：集成、回归和本机验收 | Codex | 隔离测试、真实网页/飞书闭环、脱敏验收记录；保持旧输出和思源能力可用 |

先完成 F1 的场景与契约，再并行 F2/F3 和 F4，最后完成 F5。修改与测试不用 codeagent。本文本身不启动功能开发或真实模型调用。

### I1 完成门槛

| 场景 | 必须观察到的结果 |
| --- | --- |
| 网页、飞书正常交卷 | 原回答保存一次，产生一次点评，两处读取同一结果；无需用户再去高级工具找入口 |
| 空回答、无模型配置、开关关闭、零额度或已超限 | 按实际条件拦截或保存并提供本地自查；不发生未安排的模型调用 |
| 重复事件、重复操作、在途重启 | 不重复保存回答或发送相同点评请求；结果不明的调用不会盲目重发 |
| 超时、鉴权失败、无效 JSON、无效引用或评分字段 | 原回答仍在，失败有可理解的状态且计入次数，不伪造成功反馈 |
| 证据不足、长回答、预算边界 | 未知项保留未知，覆盖范围清楚，输入/输出与每日次数均有界 |
| 切题、档案更新、来源变化或权限撤销 | 旧反馈不污染新题；历史仍可查看，外发与结果提交遵守当前授权 |
| 原有流程回归 | 当日题目与草稿稳定，自动提炼次数规则不变，已有思源复习和导出继续可用 |
| 真实闭环 | 在明确额度内完成至少一次真实交卷、点评与飞书/网页一致性检查；标注模型建议及未验证项 |

后端测试只在源码隔离副本运行，使用合成数据与假上游；真实模型验收单独进行并记录次数。前端由 Kimi 实现，Codex 做集成验证。只改文档时不运行应用测试，也不改运行配置。

## I2：按目标查看学习进度——I1 验收后的候选迭代

- [ ] 在一个简洁入口查看目标对应的练习、提交时间、帮助程度、点评来源、待核对项和下一步。
- [ ] 将“完成了一次回答”和“表现达到某项标准”分别呈现；无提示作答与借助 AI 的输出保留区别。
- [ ] 网页与飞书进度查询读取同一份记录，常规统计不调用模型；不新增用户手工维护的进度表。
- [ ] 档案变动保留历史目标和证据，不生成没有依据的掌握百分比。

完成门槛：每条进度都能追溯到题目、原回答及反馈来源；零记录、档案变动和重复提交下结果仍正确。此阶段尚未实施。

## I3：主动复习与再次尝试——依赖 I2

- [ ] 明确区分“查看今日练习”和“进入到期记忆复习”；后者复用现有思源能力，不引入第二套算法改写同一卡片。
- [ ] 按已有表现安排一次延后独立回忆或新情境练习，保留原回答与本次的新结果。
- [ ] 飞书与网页都能开始、稍后或暂停，遵守用户时间预算；不替换正在写的当天练习。

完成门槛：一次真实复习或再次作答能写入可追溯的新记录，暂停、重复消息和重启不造成重复评分或提醒。此阶段尚未实施。

## 范围与维护

本轮不迁移到 Notion、不扩展默认采集范围、不建立新聊天客户端，也不建设多租户或云端常在线服务。相关候选工作保留在 [长期路线](ROADMAP.md)。

每个迭代验收后：更新本文复选项、[实施状态](IMPLEMENTATION-STATUS.md) 和对应验收证据，再进入下一优先级。计划变更记录原因与对用户操作、时间预算和数据的影响；没有验收证据的条目继续标为未完成。
