# 知行产品路线图

更新：2026-10-30。本机已部署本地单用户 Beta 0.4.0，完整回归与一次既有回答的真实 DeepSeek 点评通过；飞书学习卡片仍待用户扫码及真实按钮闭环验收。本文是 Product Roadmap，描述目标、顺序与验收门槛；短期执行见 [迭代计划](NEXT-ITERATION.md)。阶段按优先级排列，具体依赖在各阶段说明；云端发布以 GitHub Release 为准。

## 产品目标与依据

让已经授权的日常工作对话，持续转化为与职业目标相关的学习、独立输出和复习，减少用户管理资料与维护流程的负担。

- 已知约束：用户的时间、注意力和模型预算有限；采集范围需要明确授权，后台依赖实际运行的服务。
- 已知事实：保存回答、收到反馈、延迟后独立回答和在新情境应用，分别需要不同的记录支持。
- 待验证假设：自动点评、进度对话和自适应安排能减少管理负担，并改善学习表现。实现功能不能替代效果验证。
- 排序依据：先补齐一次学习的反馈闭环，再积累进度证据，最后依据证据调整学习安排。单纯按功能数量推进会掩盖这些依赖。

日常主流程保持简单：**看到重点 → 独立回答 → 获得反馈 → 按安排复习**。目标、范围、通道和预算集中配置；后台维护不应变成每天的必做任务。

## 阶段 R1：完成回答后的反馈闭环

状态：0.4 已部署，最终回归及一次既有回答真实模型点评完成；用户扫码、真实按钮和新交卷后的网页／飞书卡片闭环尚待验收。执行范围与门槛见 [近期迭代](NEXT-ITERATION.md)及[验收记录](ANSWER-ADVICE-VERIFICATION-20261030.md)。

用户结果：在网页或飞书提交后，得到针对本次回答的简短点评，知道遗漏、待核对之处和下一步改进动作。

- 交付：接入已有模型反馈能力，沿用已配置模型（本机为 DeepSeek）；点评关联题目要求、回答片段及可用来源。
- 交付：显示准备中、已完成、失败或本地自查等实际状态；已有输出在失败和重启后保留。
- 依赖：独立的点评预算、持久任务与防重发机制；提炼的每日额度不自动覆盖新增点评费用。
- 验收门槛：两个入口共享同一份反馈；重复消息或刷新不重复发起模型请求；结果不明时保留状态，超限与模型不可用时明确保留自查路径。
- 解释边界：AI 点评属于有依据的建议，事实缺少核对依据时保留未知；单次点评不生成“已经掌握”的结论。

## 阶段 R2：可追溯的进度与主动复习

状态：按目标进度与跨次安排仍在计划中。按用户优先级，原生记忆闪卡及建议保存／暂不采纳已提前接入 0.4 源码，用户扫码和真实按钮验收仍待完成，见 [学习卡片](FEISHU-LEARNING-CARDS.md)。

用户结果：直接知道某个目标最近练了什么、哪里反复出错、今天应该回顾什么。

- 交付：按目标串联题目、原始回答、帮助程度、反馈来源、日期与后续重练，提供简短进度摘要。
- 交付方向：将用户确认的可复用结论关联回知识与思源，保留来源、修订和待核对项；新证据可形成纠正记录，不自动覆盖用户原笔记。
- 交付：把到期复习与针对薄弱点的重练接到日常入口，支持主动开始、稍后和暂停，保留未完成草稿。
- 依赖：稳定的题目与尝试标识、来源及档案版本、复习会话与完成记录；历史记录保持可追溯。
- 验收门槛：网页与飞书读取相同记录；帮助程度未知时仍标为未知；目标变化不覆盖旧记录；查询与既有题目投递不调用模型。
- 调度边界：已有思源卡片继续使用原生调度；应用练习与原生记忆卡片分别记录，避免两套算法改写同一卡片。

## 阶段 R3：围绕进度的 AI 交互

状态：长期计划；依赖 R2 的可靠记录与受限检索。

用户结果：可以询问“我最近哪里有进步”“这个目标下一步练什么”，得到可追溯的回答和一项可执行建议。

- 交付：以用户明确目标和相关练习记录为上下文，引用具体日期、回答或反馈，说明证据覆盖范围。
- 交付：区分完成次数、模型建议、用户自评与独立表现；没有足够记录时说明缺少哪些依据。
- 依赖：有界上下文、单独可见的对话预算、来源权限与历史版本过滤；无需反复加载全部 Codex 历史。
- 验收门槛：每项进步判断能追溯到记录；无记录时不补造；关闭 AI 交互后本地进度与复习仍可用。
- 入口选择：优先复用网页与飞书已有上下文；独立聊天界面按实际使用需要决定。

## 阶段 R4：依据表现调整学习安排

状态：探索与长期计划；依赖 R2 的多次表现记录，效果需另行验证。

用户结果：学习安排逐步贴近职业目标和实际薄弱点，提示量、任务难度与回顾内容有可解释的调整依据。

- 交付方向：从解释、举例到新情境应用；结合延迟后回忆、重练结果和帮助程度提出后续任务。
- 交付方向：把用户职业目标拆成可练习技能，并关联具体输出证据与用户设定的优先级；目标变更保留版本。
- 交付方向：允许查看调整依据、跳过建议、纠正判断；每日时间预算和暂停设置优先于追加任务。
- 依赖：可比较的任务与评价标准、帮助记录、延迟表现及用户反馈；自动化规则应能回退。
- 验收门槛：安排变化能指出对应记录；单次模型分数不直接转成掌握率；证据不足时维持保守安排。
- 效果门槛：通过预先定义的学习表现与负担测量，检验调整是否有益，再扩大自动安排范围。

## 阶段 R5：稳定分发、跨设备与商业化准备

状态：条件性长期计划；按照实际使用需求选择子项，不要求同时开展。

用户结果：能够可靠安装、更新和恢复资料，并在明确的部署方式下持续使用。

- 稳定分发：完善安装与更新、备份恢复、错误诊断和升级回退；保留现有数据、桌面入口与可用 API。
- 跨设备：若需要电脑关机后手机仍可学习，再设计常在线服务或受限缓存与同步；明确离线、冲突和断线状态。
- 通道扩展候选：验证并补齐网页建群、选群或话题绑定，单独明确接收人、数据可见范围与群权限；个人私聊继续可用。
- 商业化准备：核查选定依赖与分发方式的许可义务、代码和数据权属、凭据隔离、删除导出、运维与支持成本。
- 多用户准备：只有需求明确后再加入身份、租户隔离和相应安全验证；当前单用户实现不直接视为多用户产品。
- 验收门槛：在目标部署方式中完成安装、升级、恢复和权限测试；成本与数据流可说明，相关许可问题有明确核查结果。

## 共同约束与研究验证

- 飞书保持可选通道，学习核心继续由知行保存；现有思源连接保留，新增知识工具连接按明确需求评估。
- 当前“配置一次、每日少量输出”的方向沿用 [简化目标](SIMPLICITY.md)；每次迭代记录新增必需操作、跨页次数、等待与失败恢复负担。
- 生成条数、推送量与签到用于描述活动；学习效果另看独立解释、延迟回忆和新情境应用，并标明评价来源及帮助程度。
- CHI 研究按 [研究草案](CHI-RESEARCH-PLAN.md) 独立推进，保留已冻结对照版本；单人使用验收与正式效果结论分开记录。
- 飞书实现细节保留在 [通道方向](CHAT-CHANNEL-DIRECTION.md) 和 [接入说明](FEISHU-CHAT.md)，总优先级以本路线图为准。
