# 思源升级后的知行启动修复 · 0.3.3

## 原因

本机思源已从 3.8.8 升级为 3.8.9，专用工作区和端口 19006 均正确。桌面快捷方式指向正确的 `start-all.cmd`，但启动器将任何非 3.8.8 版本判为错误服务，并在启动知行后台之前退出。

因此打开桌面入口仍可能没有知行服务监听 18997；飞书随知行后台运行，也无法在此期间推送。此次只根据实际版本响应与启动顺序确认阻断，没有还原用户当时的控制台日志。

## 修改

- 有效的思源版本响应分为“已验证”和“尚未验证”。尚未验证版本只警告，不阻断知行后台和飞书启动。
- 启动器仍核对专用工作区、固定端口及有效响应；无效响应、其他服务和错误工作区不能被宽容版本检查绕过。
- 思源同步与原生卡片评分仍使用后端原有兼容性检查。放宽后台启动不代表已验证新版本的 Riff 契约。
- 不安装、停止或降级现有思源，不修改它的笔记或卡片；用户继续使用原桌面入口。
