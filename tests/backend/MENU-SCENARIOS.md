# 飞书菜单需求与验收场景

目标：发送“菜单”得到可点击入口；收到命令后，即使卡片投递失败也有简短提示。打开菜单和状态不调用模型，不把命令当作作答，不重放旧的未确认投递。0.6.0完整后端1042项、打包45项通过；联调165、渲染46、发送层33为重叠专项，不相加。部署、平台接受与真实按钮边界见 [验收记录](../../docs/FEISHU-MENU-VERIFICATION-20261031.md)。菜单服务及API场景对应 `feishu-menu.test.mjs`，渲染对应 `feishu-cards.menu.test.mjs` 与原卡片测试。

| 编号 | 必须结果 | 验证范围 |
| --- | --- | --- |
| M1 | 菜单命令及帮助别名优先于讨论／作答；重复消息只产生一次菜单操作 | 菜单服务测试 |
| M2 | 无今日练习仍可打开菜单；卡片关闭时返回可用文字说明 | 菜单服务测试 |
| M3 | 四个固定入口、单一主操作、短文案；所有旧卡片呈现兼容 | 菜单渲染及原卡片测试 |
| M4 | 菜单读取当前题目并更新同一条已确认消息；旧uncertain投递及UUID不变 | 菜单服务测试 |
| M5 | 题目更新未确认前不能作答；确认后原有文字回复及表单提交可用，重复操作不重复记录 | 菜单服务测试 |
| M6 | 查看已有建议和状态不生成新建议、不创建回答或成果、不调用模型 | 菜单服务测试 |
| M7 | 记忆闪卡复用现有复习；无题、无到期卡及连接异常有明确状态 | 菜单服务测试 |
| M8 | 其他用户／会话／绑定／应用、旧nonce、未确认消息及已撤销来源不能执行或发布操作 | 菜单服务及原卡片权限测试 |
| M9 | 明确请求的卡片进入终态失败或未知时至多创建一条文字提示，不递归提示、不重发原卡片 | 菜单服务测试 |
| M10 | 平台结构化非零错误码识别为已拒绝，只保留安全错误码；权限及限流映射保持 | `feishu-channel.test.mjs` |
| M11 | 断连、超时、无业务码HTTP错误及残缺响应保持未知；发送和更新各只请求一次 | `feishu-channel.test.mjs` |
| M12 | 打开菜单API沿用本地客户端、操作ID及写入去重；不伪造个人收件或作答 | 菜单API测试 |

后端仅在受保护的源码隔离副本串行运行，测试数据位于物理隔离目录；真实模型、生产思源及个人数据不作为测试夹具。纯模拟测试不证明平台已送达或用户完成了按钮闭环，真实部署与投递另行记录。
